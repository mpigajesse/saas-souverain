AmānFramework SaaS Souverain
La donnée métier reste sur les machines du client. L'éditeur gère comptes et licences — et reste cryptographiquement incapable de lire les données de ses clients.
Le problème
Comment un éditeur peut-il vendre et maintenir un logiciel métier en mode SaaS (comptes, licences, mises à jour) sans jamais accéder aux données de ses clients — conformément au cadre africain de protection des données (AUDPF) ?
L'architecture — trois acteurs, une frontière chiffrée
🏢 Chez l'éditeur — ne voit jamais les données métier

🔐 Frontière cryptographique — tout sort chiffré (DEK · libsodium)

Nœud primaire

Exécute le logiciel, détient et chiffre les données. PostgreSQL primaire (écritures).

PRIMAIRE · actif
🖥️

Nœud standby

Réplique en continu. Lecture seule. Prend le relais par quorum si le primaire tombe.

STANDBY · réplica
⟲ Réplication streaming PostgreSQL < 1 s  ·  fencing par jeton d'époque (anti split-brain)
La clé DEK — une seule clé par entreprise, jamais vue par l'éditeur
🔑 DEK

Clé symétrique unique par entreprise. Chiffre les données métier + le journal CBOR avant tout écrit disque.

→
📲 Par appareil

La DEK est emballée en sealed box (X25519) pour chaque appareil autorisé. Enrôlement par QR code : perspective.

→
🆘 Récupération

Emballée sous un code haute entropie (Argon2id) → blob chiffré stocké sur le relais. L'éditeur ne déchiffre rien.
